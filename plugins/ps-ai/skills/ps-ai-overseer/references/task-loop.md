# Task loop

Use the terms and work sizes in [the overseer skill](../SKILL.md#terms-and-work-size).

1. Read the task from the plan and its spec. For ad hoc delegation, write one explicitly scoped brief from the owner's request; no milestone plan is needed. In either case, dispatch inside the assigned repository worktree. Put the available spec and plan, rules file, base commit, file scope, report path, checks, commit message, and stop points into [prompts/task.md](prompts/task.md). For an ad hoc brief, omit absent plan/spec inputs from the prompt. Keep every task input inside that worktree; copy ignored inputs into its `.agents/temp/` before dispatch if needed, and pass the local absolute paths. Use `ps-ai-legion` for the worker contract; do not duplicate it in the prompt.
2. Follow [owner notes](../../ps-ai-personalisation/references/fields.md) and repository workflow before dispatch. Ping through its tool skill before declaring it out of credit. If no legion account is usable, follow [milestone-flow.md](milestone-flow.md#execution-choice) for a milestone. For ad hoc work, do it in the session if possible or record the blocked next action and tell the owner.
3. Create task prompt/report/log paths under the assigned worktree's `.agents/temp/`. Write a handoff row and next action to disk **before** the tool skill launches the process. Use `skills/ps-ai-<agent.tool>/SKILL.md` and its run reference (stop if the tool skill is missing) with `PS_AI_ROLE=legion` and `PS_AI_TASK=<prompt path>` on that process only. Set the process working directory to the assigned worktree and inherit the owner's environment. Legion runs without a sandbox; dispatch only the plan task or scoped ad hoc brief, inside that worktree. Long work runs in the background; wait for completion, do not poll logs. A simulation describes the proposed run without executing it; show commands only when requested or when the owner must run them themselves.
4. Read the report and inspect status, commit message, changed-file list, and the risky change against the task scope. Check tests, script results, open questions, encoding, and user rulings. Fixed before/after gates come from `workflow.md` and `scripts/index.md`. Never run a missing or unindexed gate.
5. If a real defect remains, add the scoped fix to the plan or ad hoc brief before dispatch. A scope or API question goes to the owner. If a worker reports a missing or wrong-version tool, stop dispatching the blocked task and ask the owner how to proceed; do not tell legion to download or install it. If an account ran out mid-task, save a patch and fresh-run on another routed account; resume only on the original account and folder. Do not amend or force-push. Record the result, clear the row, and write the next handoff state before the next task; commit it with the task's stage.

Legion writes its report; overseer alone writes handoff. Delivery follows `workflow.md` and owner rulings. Do not merge to main for `merge-request` delivery.
