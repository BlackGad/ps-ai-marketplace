# Create owner configuration

1. Ask one question at a time, in order: communication language and question cadence; channels or none; agents and existing wrappers; account roles/models; routing; knowledge; notes. Use answers already given without re-asking. Ask only for missing choices that block a valid file.
2. Create `<home>/.agents/configuration/ps-ai-personalisation.json` with the schema's required top-level fields: `schemaVersion: 1`, `communication.channels`, `agents`, `routing`, `knowledge.backend`, `projects`, `default`. See [fields.md](fields.md). Empty routing lists and `knowledge.backend: none` are valid while choices remain open. Validate this initial JSON.
3. Handle each account through the selected tool skill's `references/accounts.md`. The JSON must exist first. Before adding an account, check whether its CLI is installed. If it is missing, offer to install it in plain words, wait for the owner's yes, and follow that tool skill's `references/install.md`; continue adding the account only after the CLI is available. For an existing folder without a shortcut, use `-Action add -ConfigDir <existing folder>`; this records the supplied folder and creates a wrapper for it. For an existing wrapper, use `-Action register -Command <wrapper> -ConfigDir <folder>`. Do not replace an existing wrapper, edit account settings, read credentials, or recreate its login. Account IDs may not shadow a command on PATH; the command and account id may differ. Explain that ps-ai will be installed into the account, get the owner's yes, then run the guide's shared `install.ps1` command with `-Yes`. Use approval already given without re-asking. Do this for every added, adopted, registered, or Foundry account; validate afterward. If installation is declined or fails, report that account setup is incomplete and keep its existing settings and login.
4. Add roles, models, launch arguments, and routing according to owner answers. Before saving the first legion routing, including a project override, explain and ask in plain words: "Legion workers run without a sandbox and with your full user rights, so they can edit, run checks, and commit using your installed tools. Sandboxes can hide installed tools; agents then download their own SDKs and drift from your machine's setup. Workers must stay inside their assigned repository or worktree, never push or touch other folders, and never download or install SDKs, runtimes, package managers, or tools. If a tool is missing or the wrong version, they stop and report it so the overseer can ask you. These are instructions, not an enforced access boundary. Route legion only to accounts you trust, or leave legion unused. Do you want to enable legion routing?" Wait for a yes before saving it; use an explicit answer already given in this conversation without re-asking. If declined, leave legion routing empty. Record no new field or consent note. For new accounts use the matching tool skill and `-Action add`; the owner logs in themselves. Never handle credentials.
5. Create `ps-ai-notes.md` from [notes-template.md](notes-template.md) with stated preferences. Install the launcher shim using [launcher.md](launcher.md) if setup includes it. Re-read files and validate final JSON.

In a temporary owner home, substitute it for every `~` and pass `-HomeRoot <temp home>` to every account or launcher script. `ps-ai-validate.ps1` has no `-HomeRoot`; pass the temp home's full JSON path with `-Path`.
