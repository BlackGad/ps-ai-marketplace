# Overseer launcher

`ps-ai-setup.ps1` writes `ps-ai-setup`, `ps-ai-status`, `ps-ai-overseer` and `legion` into `<home>/.legion/bin`. On Windows it adds that folder to PATH; on macOS and Linux it prints the line to add; `ps-ai-refresh.ps1` retargets them after an update. Never hand-write the shim. A different file with the same name is kept and reported as blocked.

Usage: `ps-ai-overseer [-Account <id>] [-Tool <tool-id>] [-Channel <id[]>] [-NoChannel] [-Arguments <string[]>] [-Repo <path>]`. `-DryRun` prints the arguments without opening a window; in a fixture pass `-HomeRoot <temp home>`.

`-Account` is optional. A start with no account, tool, channel or arguments repeats the last launch in that repository (account, channels and arguments, kept in `<home>/.legion/state/overseer-launches.json`) while that account exists; every other launch becomes the new last one. Without a last launch, one account (after `-Tool` and `-Channel` narrowing) is picked; with several, the launcher lists the ids and stops, so pass `-Account <id>` explicitly. When exactly one channel binding fits the account and the tool, it is added by default; `-NoChannel` skips it and `-Channel <id[]>` overrides it. On success it prints `launched <id> (<tool>) in <repo>`.

Omit model flags by default. When owner notes name a model or allow a tier, follow [model guidance](../../ps-ai-overseer/references/task-loop.md#model-tiers) and pass the flag through literal `-Arguments`. Follow [owner notes](fields.md) for account and channel choices; prefer the current account when bound and its session tools are available, otherwise name a supported bound alternate before an authorized relaunch. A direct launcher run is itself a request to launch; simulations describe actions without running them. Any owner-started session may take the lease without a channel. Follow the overseer communication guide's handoff, release, launch and stop order. Read the tool skill's `references/launcher.md` for account, model and channel examples. On Windows the launcher uses Terminal when available and clears `NO_COLOR`, `TERM` and the calling Claude session's variables (`CLAUDECODE`, `CLAUDE_CODE_*`) in the new session, so the overseer is saved as its own session and can be resumed; always launch through this script, never a hand-built terminal command.
