# Overseer launcher

`ps-ai-setup.ps1` writes `ps-ai-setup`, `ps-ai-status`, `ps-ai-overseer` and `legion` into `<home>/.legion/bin`. On Windows it adds that folder to PATH; on macOS and Linux it prints the line to add; `ps-ai-refresh.ps1` retargets them after an update. Never hand-write the shim. A different file with the same name is kept and reported as blocked.

Usage: `ps-ai-overseer [-Account <id>] [-Tool <tool-id>] [-Channel <id[]>] [-NoChannel] [-Arguments <string[]>] [-Repo <path>]`. `-DryRun` prints the arguments without opening a window; in a fixture pass `-HomeRoot <temp home>`.

`legion` or `ps-ai-overseer` with no account, tool, channel, arguments or `-NoChannel` repeats the last launch in that repository, including a launch without channels. The account, channels and arguments are kept in `<home>/.legion/state/overseer-launches.json`; dry runs leave it unchanged. If no saved launch has an account that still exists, a bare `legion` uses the account that last held the repository's overseer lease, if it still exists. Otherwise, one eligible account (after `-Tool` and `-Channel` narrowing) is picked; with several, the launcher lists the ids and stops. Choose with `legion pick`, which lists the accounts and asks, or `ps-ai-overseer -Account <id>`. When exactly one channel binding fits the account and the tool, it is added by default; `-NoChannel` skips it and `-Channel <id[]>` overrides it. Every launch except a dry run becomes the new last launch. On success it prints `launched <id> (<tool>) in <repo>`.

Omit model flags by default. When owner notes name a model or allow a tier, follow [model guidance](../../ps-ai-overseer/references/task-loop.md#model-tiers) and pass the flag through literal `-Arguments`. Follow [owner notes](fields.md) for account and channel choices; prefer the current account when bound and its session tools are available, otherwise name a supported bound alternate before an authorized relaunch. A direct launcher run is itself a request to launch; simulations describe actions without running them. Any owner-started session may take the lease without a channel. Follow the overseer communication guide's handoff, release, launch and stop order. Read the tool skill's `references/launcher.md` for account, model and channel examples. On Windows the launcher uses Terminal when available; otherwise it runs in the current terminal. Both paths clear `NO_COLOR`, `TERM` and the calling Claude session's variables (`CLAUDECODE`, `CLAUDE_CODE_*`) for the new session, so the overseer is saved as its own session and can be resumed. Always launch through this script, never a hand-built terminal command.
