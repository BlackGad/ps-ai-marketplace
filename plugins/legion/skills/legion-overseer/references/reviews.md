# Independent reviews

Freeze a worktree at the review commit under `.legion/temp/floor-<n>/`; reviewers read that commit and cannot edit the checkout. Follow [owner notes](../../legion-personalisation/references/fields.md); owner preferences always win. Save newly stated preferences using the [shared memory rule](../../legion-personalisation/SKILL.md#identity-and-hard-rules). Without preferences, choose a different tool/provider from the implementing agent and spread reviews across available agents. Say which agent was chosen. Pass no model by default. Follow [model tiers and the one-time cost question](task-loop.md#model-tiers) before choosing a review model. Do not discover models or offer model lists for subscription agents. Require tool-enforced read-only access through the selected tool skill; stop if the tool cannot enforce it. Reviewer content comes from an installed review skill when present; legion owns dispatch and synthesis.

Before dispatch, prepare the worktree's configuration and scripts using [lanes.md](lanes.md), including the Private copies. Send the same [prompts/review.md](prompts/review.md) brief to each reviewer, with repo rules, spec, plan rulings, base and review commit. Keep reports separate; no reviewer sees another's report. Use one independent verifier per report with [prompts/verify.md](prompts/verify.md). Confirm or refute each finding against file:line evidence. Record refutations and reasons in milestone history.

Merge confirmed findings by underlying rule and owner type. Rank agreement between independent reviewers first, then severity; report at most one screen to the owner. Ask for the fix round before dispatching [prompts/fix.md](prompts/fix.md). A review never edits the frozen checkout. If the requested diversity of tools/providers cannot be met with configured accounts, record the limitation and ask the owner how to proceed.
