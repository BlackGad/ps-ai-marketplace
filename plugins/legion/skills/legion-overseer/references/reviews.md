# Independent reviews

Freeze a worktree at the review commit under `.legion/temp/floor-<n>/`; reviewers read that commit and cannot edit the checkout. Follow [owner notes](../../legion-personalisation/references/fields.md); owner preferences settle only the roles they name. Save newly stated preferences using the [shared memory rule](../../legion-personalisation/SKILL.md#identity-and-hard-rules). Follow [default routing](task-loop.md#default-routing) for every choice the owner left open; the reviewer is always distinct from the author, and if the owner's choices assign the author to review their own code, ask the owner to resolve it. Pass no model by default. Follow [model tiers and the one-time cost question](task-loop.md#model-tiers) before choosing a review model. Do not discover models or offer model lists for subscription agents. Require tool-enforced read-only access through the selected tool skill; stop if the tool cannot enforce it. Reviewer content comes from an installed review skill when present; legion owns dispatch and synthesis.

Before dispatch, prepare the worktree's configuration and scripts using [lanes.md](lanes.md), including the Private copies. Send the same [prompts/review.md](prompts/review.md) brief to each reviewer, with repo rules, spec, plan rulings, base and review commit. Keep reports separate; no reviewer sees another's report. Use one independent verifier per report with [prompts/verify.md](prompts/verify.md). Confirm or refute each finding against file:line evidence. Record refutations and reasons in milestone history.

Merge confirmed findings by underlying rule and owner type. Rank agreement between independent reviewers first, then severity; report at most one screen to the owner. Ask for the fix round before dispatching [prompts/fix.md](prompts/fix.md). A review never edits the frozen checkout. If [default routing](task-loop.md#default-routing) or the owner's requested diversity cannot be met with configured accounts, record the limitation and ask the owner how to proceed.
