# Takeover and handoff

Reconcile all promised future outcomes under [pending results](pending-results.md), including hosted checks and external jobs as well as worker rows.

Activate only on the owner's request in a repo with `.legion/state`; `LEGION_ROLE=member` disables the overseer. Load personalisation and notes, then repo rules, `.legion/configuration/project.json`, `.legion/configuration/workflow.md`, `.legion/scripts/index.md`, and the handoff. Read the named plan and relevant spec when present.

Read `.legion/state/handoff.md`, recent history, code status and code commits. If `.legion/.git` is a folder, also read the inner Git status and log. The handoff headings are exactly: Branch; Goal and milestone; State; Current task; Legion running; Next action; Open decisions; Postponed; Recent evidence. Record the goal id or `none`, milestone or `none`, and code base commit under `Goal and milestone`. Load `.legion/state/roadmap/<goal-id>.md` for the named goal. Follow [roadmap.md](roadmap.md) for switching and goal selection. No roadmap is needed for standalone milestones or ad hoc work.

Read status with the plugin's `legion` MCP `status` tool first, falling back to `legion status --json` if startup fails. For selected-account limits use its `limits` tool first; follow [selection, side effects and CLI fallback](read-tools.md). Members never call these tools.

Commit handoff, history, and roadmaps in the Git repository that owns `.legion/state`. Private uses `git -C <repo>/.legion` with paths such as `state/handoff.md`; Shared uses `git -C <repo>` with `.legion/state/...` paths. Keep code commits in the outer repo. Stage only the intended files.

Only the lease holder edits the handoff and roadmap files. Keep the handoff short; archive finished milestone details in `state/history/`. Ad hoc work records only what must survive the session, such as a running legion task, its review, or a blocked next action. Do not invent a milestone or write every ad hoc question to the handoff.

The lease is `.legion/temp/overseer.lock`. Use `legion lease status --repo <repo>`, `legion lease take --repo <repo> --tool <tool> --account <id>` and `legion lease release --repo <repo>` for every lease operation; never write or delete the lock directly. `take` creates the lock exclusively and writes `tool`, `account`, `pid`, `processStartedAt`, `host` and `startedAt`, plus `session` for a Codex thread. The default owner is the nearest non-shell ancestor (the long-lived agent CLI session); shell helpers are skipped. If only shell ancestors survive, the oldest reachable shell owns the lease. The PID and process start time always come from that same owner. Pass `--process-id <pid>` to `take` or `release` to override it explicitly. A lock without `processStartedAt` is invalid and stale. For a valid lock, a local PID with the recorded process start time is held, a dead or reused PID is stale, and a different host is foreign. On held or foreign, tell the owner and wait; a foreign lease is unknown, not automatically stale. On stale, take over: the owner's request to continue already authorizes replacing a stale lease, so do not ask again. Host names compare without case (`HOST-A` and `host-a` are the same machine). Keep the lease while waiting for the owner, because nudges and channel messages go to the lease holder; release it with `legion lease release` only when the owner ends overseer work or hands over. Do not infer member mode from a lease.

For each `Legion running` row, check in this order:

| Evidence | Action |
| --- | --- |
| Process alive | Wait for completion; do not duplicate the run. |
| Report present | Immediately write `State: reviewing task N report` and `Next action: review report, then indexed gates` before running the gate or another task action. Read `legion-member/references/report-format.md`, review the report, commit, scope, checks, and questions. Record result; remove the running row. |
| Task commit present, report absent | Review from the commit and plan or scoped ad hoc brief; record the missing report and result. |
| No report or task commit | Save staged and unstaged tracked work with `git diff --binary HEAD` into a patch under `.legion/temp/`. List untracked files with `git ls-files --others --exclude-standard` and copy them separately under `.legion/temp/`, preserving their relative paths. Record the patch and copy paths in the handoff. Relaunch through the matching tool skill, same account for resume or another routed account with patch and a fresh prompt. In a dry-run scenario, describe the proposed relaunch without executing it; show commands only when requested or when the owner must run them themselves. |

After every row is checked, report status in the owner's preferred style using the shared [terms](terms.md). Write the reconciled handoff before new dispatch or milestone questions. At launch time, write the new row with account, task, prompt/report/log paths, base commit, and start time; set next action to `wait for task N, then review` before starting the tool. This applies to ad hoc legion runs too. After completion, record commit/check/report evidence, remove its row, and set the next action. Each milestone step and owner question gets a write-ahead handoff update, written to disk at once and committed with its stage. Questions before taking the lease write nothing.
