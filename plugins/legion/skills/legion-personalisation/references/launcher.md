# Overseer launcher

`legion-setup.ps1` copies the plugin into `<home>/.legion/app/<version>` and writes `legion` into `<home>/.legion/bin`; the command runs that copy through uv (`uv run ... legion`), which hands verbs not yet in Python to `bin/legion.ps1`. Without uv it prints one line and exits 127. On Windows it adds that folder to PATH; on macOS and Linux it prints the line to add. Setup and the installer's refresh write the command. The "Generated by legion" header owns the whole file: hand-added text is replaced, and a headerless file is never changed. Install targets share the recorded command; uninstall refreshes it from a remaining target or removes it after the last one leaves. Never hand-write the shim. A different file with the same name is kept and reported as blocked.

Usage: `legion [--account <id>] [--tool <tool-id>] [--channel <id> [--channel <id> ...]] [--no-channel] [--argument=<word>] [--repo <path>]`. `--dry-run` prints the arguments without opening a window; in a fixture pass `--home <temp home>`.

Bare `legion` with no account, tool, channel or arguments repeats the last launch in that repository, including a launch without channels; adding only `--no-channel` (or `legion pick` choosing the saved account) restores the saved account and arguments, then clears the channel. The account, channels and arguments are kept in `<home>/.legion/state/overseer-launches.json`; dry runs leave it unchanged. If no saved launch has an account that still exists, a bare `legion` uses the account that last held the repository's overseer lease, if it still exists. Otherwise, one eligible account (after `--tool` and `--channel` narrowing) is picked; with several, the launcher asks which account leads; without a console it lists the ids and stops. Choose with `legion pick`, which lists the accounts and asks, or the launcher's `--account <id>`. When exactly one channel binding fits the account and the tool, it is added by default; `--no-channel` skips it and `--channel <id> [--channel <id> ...]` overrides it. Every launch except a dry run becomes the new last launch. On success it prints `launched <id> (<tool>) in <repo>`.

Omit model flags by default. When owner notes name a model or allow a tier, follow [model guidance](../../legion-overseer/references/task-loop.md#model-tiers) and pass the flag through literal `--argument`. Follow [owner notes](fields.md) for account and channel choices; prefer the current account when bound and its session tools are available, otherwise name a supported bound alternate before an authorized relaunch. A direct launcher run is itself a request to launch; simulations describe actions without running them. Any owner-started session may take the lease without a channel. Follow the overseer communication guide's handoff, release, launch and stop order. Read the tool skill's `references/launcher.md` for account, model and channel examples. On Windows the launcher uses Terminal when available; otherwise it runs in the current terminal. Both paths clear `NO_COLOR`, `TERM` and the calling Claude session's variables (`CLAUDECODE`, `CLAUDE_CODE_*`) for the new session, so the overseer is saved as its own session and can be resumed. Always launch through this command, never a hand-built terminal command.

For commands, use `legion <verb>`; if `legion` is not on PATH yet, run `<home>/.legion/bin/legion` (`legion.cmd` on Windows); if that file is missing too, finish setup first.
Account, channel and repository verbs run through this owner command: `legion account add --id <id> --tool <tool>`, `legion account remove --id <id>`, `legion channel add --id <id> --kind telegram --target <chat> --account <account>`, `legion channel check --kind telegram --account <account>`, `legion channel remove --id <id>`, and `legion repository setup --repo <path>`. `legion refresh` repairs owned launchers.
