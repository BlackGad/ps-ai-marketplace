# ps-ai plugin Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the `ps-ai` plugin (eight skills, mode hook, overseer launcher, account and validation scripts) in a marketplace that installs into Claude Code, Codex CLI and Copilot CLI.

**Architecture:** One plugin folder `plugins/ps-ai/` with three manifests (Claude, Codex, Copilot) over one `skills/` tree. Deterministic behaviour lives in PowerShell 7 scripts with tests (`hooks/detect-mode.ps1`, `bin/*.ps1`, `install/install.ps1`); judgement lives in `SKILL.md` files with detail in `references/`. Skills are verified with baseline and guided runs.

**Tech Stack:** PowerShell 7.6 (`pwsh`), JSON Schema draft 2020-12 via `Test-Json -SchemaFile`, Markdown skills, Claude Code 2.1.325, Codex CLI 0.167, Copilot CLI 1.0.109.

**Spec:** `docs/specs/2026-11-18-ps-ai-design.md` (read it whole before any task; section numbers below refer to it).

## Global Constraints

- All skill names start with `ps-ai-`; frontmatter `name` equals the folder name; `description` starts with `Use when` and states triggers only.
- **REQUIRED for Tasks 7-11: the `standards-skill-writing` skill** (`<skills>/standards-skill-writing/SKILL.md` and its `references/`; owner ruling 2026-11-18). Read it whole before the task and follow its Flow A (create) exactly: classify the type by primary job, read nearby skills, load the matching references, baseline first, write the minimal file set, verify frontmatter, workflow shape, stop conditions and the reference split, then the guided run. Tick its Verification Checklist in the verification file for each skill. Its three-zone layout applies: identity, hard rules and scope in the first 30 percent; flow and reference routing in the middle; stop conditions and the checklist at the end. Keep each `SKILL.md` under 150 lines; detail goes to `references/`, one concern per file.
- Only runtime: PowerShell 7 (`pwsh`). No other dependency is installed or required. `install.sh` only execs `pwsh install/install.ps1 "$@"`.
- Personalisation: `~/.agents/configuration/ps-ai-personalisation.json` and `ps-ai-notes.md`. Repo: `.agents/configuration/project.json` and `workflow.md`, `.agents/scripts/index.md`, `.agents/state/handoff.md` and `history/`, ignored `.agents/temp/`.
- Environment: `PS_AI_ROLE=legion` and `PS_AI_TASK=<prompt path>` mark a legion member; nothing else does.
- Lease file: `.agents/temp/overseer.lock`.
- Lane worktrees: `.agents/temp/floor-<n>/`.
- No skill or script reads, prints or logs credentials or token files; skills ask the owner to log in themselves.
- Never force-push, never amend; commits end with `Co-Authored-By:` of the agent that wrote them.
- Method skills (TDD, debugging, brainstorming, review checklists, worktrees) are referenced by name as "when installed", never copied.
- Easter eggs: only the six in spec section 14, exact text; none in owner-facing reports.
- Tests: `pwsh -NoProfile -File tests/run.ps1` runs every `tests/*.Tests.ps1` and exits non-zero on any failure. No Pester (only 3.4 is present); `tests/Assert.ps1` gives `Assert-Equal $expected $actual $message`, `Assert-True $condition $message`, `Assert-Throws { } $message`.
- Scripts never touch the real home folder in tests: every script takes the home root as a parameter (`-HomeRoot`, default `$HOME`), and tests pass a folder under `$env:TEMP/ps-ai-tests/<guid>/`, deleted at the end.

## Review Focus

1. Paths with spaces (`C:\Program Files\...`, a repo under `My Projects`) in the launcher, wrappers and installer: arguments must stay one argument each. Test in Task 4 and Task 5.
2. A malformed or missing personalisation file at session start: the hook must still print legion or hint context and never fail the session (exit 0, one warning line). Test in Task 3.
3. A stale lease from a crashed overseer, or a lease from another machine (synced folder): stale is reported as takeable; another host is reported as "unknown, ask the owner". Test in Task 3.
4. Renaming an account referenced in `routing` and in `projects.<id>.routing`: every reference changes, nothing else. Test in Task 6.
5. Windows line endings and a UTF-8 BOM in JSON and handoff files written by editors: parsing must accept both. Test in Task 2 and Task 3.

### Task 15: Tool installer

**Files:** `plugins/ps-ai/bin/ps-ai-install-tool.ps1`, `install/bootstrap.ps1`, `tests/InstallTool.Tests.ps1`; `references/install.md` in `ps-ai-claude`, `ps-ai-codex` and `ps-ai-copilot`; `ps-ai-repository/references/tools.md`; small edits to those SKILL.md files and the README.

**Interface:** `ps-ai-install-tool.ps1 -Tool pwsh|git|node|claude|codex|copilot|gh|glab|az [-Yes] [-Platform windows|macos|linux]`. Without `-Yes` it only prints the status (`installed <version>` or `missing`) and the exact commands it would run. With `-Yes` it installs only what is missing; an installed tool is `skip: <tool> already installed (<version>)`, exit 0. After installing it checks again and fails if the tool is still not found (a new PATH may need a new terminal: say so). Dot-source with `-NoRun` exposes `Get-ToolRecipe -Tool <t> -Platform <p> -> [pscustomobject]@{ Check = <string[]>; Install = [string[][]]; Needs = [string[]]; Docs = <url> }` and `Test-ToolInstalled -Tool <t> -> @{ Installed = <bool>; Version = <string> }`. The script never prompts; the skill asks the owner and passes `-Yes` only after a yes.

**Recipes** (official channels; check every winget id with `winget show --id <id> -e`, read only, and correct any that fail):

| Tool | Windows | macOS | Linux |
| --- | --- | --- | --- |
| pwsh | `winget install --id Microsoft.PowerShell -e` | `brew install --cask powershell` | docs only: https://learn.microsoft.com/powershell/scripting/install/installing-powershell-on-linux |
| git | `winget install --id Git.Git -e` | `brew install git` | docs only: https://git-scm.com/download/linux |
| node | `winget install --id OpenJS.NodeJS.LTS -e` | `brew install node` | docs only: https://nodejs.org/en/download |
| claude | `irm https://claude.ai/install.ps1 \| iex` (in pwsh) | `curl -fsSL https://claude.ai/install.sh \| bash` | same as macOS |
| codex | `npm install -g @openai/codex` (needs node) | same | same |
| copilot | `winget install --id GitHub.Copilot -e` | `npm install -g @github/copilot` (needs node) | same as macOS |
